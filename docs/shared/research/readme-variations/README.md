## What to compare

Read the opening, find the installation steps, then find a limitation. Judge which draft makes those three things easiest. The title line, mascot placement and section order can be mixed independently of the prose style.

All options retain the light/dark banner, animated mascot, original visualization and recorded demo. The visualization and demo now sit beside the evidence instead of ahead of the explanation. The demo remains expandable, as in the source. The repeated TL;DR is removed because it restated the tagline.

The benchmark values and negative results are preserved. The prose makes the unknown run date and measured setup visible. Codex remains explicitly unavailable and unmeasured; the inherited Claude artwork is labeled as Claude evidence. No new benchmark was run.

## How the chosen style could extend

For plugin editions: one clear promise, a concrete description, installation, useful actions, evidence with limits, then reference links. Keep host differences in the existing six exception blocks.

For plugin main pages: use the same promise, explanation, benefits, mechanism, examples and limitations, with an edition choice where installation would go. Keep native commands and measured tables on the edition pages.

For Foundry's root: keep the banner, explain the collection in one paragraph, then show a plugin choice table with host availability. Follow with installation by host, short product descriptions and community links. Move detailed contributor hook explanations to the contribution guide. Replace blanket cost-saving language with a qualified description consistent with Hush's evidence.

## Validation and later enforcement

All three Claude/Codex pairs pass the existing parity checker; all six files pass the navigation checker. Relative artwork, documentation and license paths point to the existing local files so these drafts can be read here.

These are design candidates, not release-ready replacements. A retains the template's section order. B and C deliberately explore other orders, and all three omit the duplicated TL;DR. The current parser checks required headings but does not enforce their order or the TL;DR. Passing it does not mean those experiments conform to the current template. Main-page coordination remains part of applying the selected design.

Once a direction is selected, update the shared README template and both native copies of the authoring skill/rule together. Extend the existing checks only for objective requirements: chosen section order, valid navigation, preserved artwork, parity and evidence declarations. Keep clarity, useful examples, repetition and unsupported promises as editorial review criteria. No new enforcement has been installed during this comparison.
