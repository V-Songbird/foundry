# Proving foreman — the axis map, the harness repair, and what the runs said

Date: 2026-08-29
Status: **Sonnet and Opus grids both run — 96 valid sessions. Harder fixtures in build.**
Harness: `benchmarks/foreman/` (public, reproducible)
Batches: `proof-sn2` + `proof-op2` (valid), `picks/proof2` (valid), `proof-sn` + `proof-op` (retired, see §0)

Goal: establish, with evidence rather than assertion, what foreman buys a
project over vanilla Claude Code — and where it buys nothing. Every claim below
is a number produced by a run, a number from a recorded prior run, or an
explicitly unmeasured hypothesis.

---

## 0. The harness had no valid foreman arm

Before any headline number is worth quoting, the arm it names has to be a
prompt foreman would actually emit. Neither candidate was.

### Candidate 1 — the hand-frozen `foreman.md`

`foreman/scripts/check-prompt.js` is the product's own mechanical gate: a
crafting session cannot hand off a prompt that fails it. Run from a neutral
working directory, so no host project's `.foreman/config.json` colours the
verdict, the frozen arm fails with six errors on all three tasks:

| Missing / wrong in the frozen arm |
|---|
| `<scope_discipline>` differs from the template, which must be verbatim |
| the fixed closing paragraph ("Reason through the approach…") absent |
| closure-evidence rule absent — required in **both** profiles |
| `<plan>` absent — every reinforced handoff carries it |
| the no-invention line ("a finding to report, not a gap to fill") absent |
| the verification fix loop is **unbounded** — no two-attempt ceiling |

`selfcheck.js` never caught it because its prompt check only verified that the
`truth_grounding` block was current, not that the whole prompt cleared the gate.

### Candidate 2 — `shape-off`, generated by `outputshape/gen.js`

Gate-clean and product-generated, so it looked like the obvious substitute. It
is not, for two reasons that only show up on inspection of the rendered prompt:

- Its `judgmentFor()` passes the task's **constraint facts** as
  `judgment.context`, and the standard profile drops `<context>`. So
  `index.js is frozen byte-for-byte` and `do not touch src/format.js` never
  reached the session. The arm was **fact-poorer** than the plain paragraph it
  was being compared against.
- Its `planned_touches` names the task's **real** file. On `moved-file` — whose
  entire design is a brief that names `src/parser.js` when reality is
  `src/tokenizer.js` — that repairs the trap before the session sees it. The
  arm scored 0/4 on "named the mismatch" for the simple reason that its prompt
  contained no mismatch to name.

Both are correct for the within-foreman A/B that generator was built for, where
fact poverty cancels out between its two arms. Both are disqualifying for a
cross-arm comparison.

### The repair

New `benchmarks/foreman/defaultarm/gen.js` produces arm **`foreman-std`**: the
same product assembler, with constraint facts mapped to `judgment.constraints`
(which renders into `<task_rules>` at either profile) and `planned_touches`
carrying the brief's **claimed** file — the wrong one included, exactly as every
other arm states it. Foreman's truth-grounding block is then what has to catch
it, which is the actual product claim under test.

The diff against `shape-off` is exactly the constraint facts and nothing else:

```
> Constraints:
> - index.js is frozen byte-for-byte — downstream consumers pin that exact file…
```

Three guards now make this un-repeatable:

| Guard | What it refuses |
|---|---|
| `defaultarm/gen.js` | writing an arm that drops a constraint fact or repairs the stale file name |
| `tests/default_arm.test.js` | a file set that differs from the `freeform` arm's; a gate-failing prompt |
| `selfcheck.js` | any generated arm that `check-prompt.js` rejects — verified to fire by feeding it the legacy prompt |

Harness suite: 66/66. `selfcheck` 5/5. The legacy `foreman` arm is kept only so
previously tagged runs stay re-reportable, and the README now says not to quote
it.

## 1. What the Sonnet grid said

`proof-sn2` — 3 tasks × 4 arms × 4 reps = 48 sessions, one interleaved batch,
`sonnet`. Zero cells flagged for rate-limit poisoning (cost 0, non-success
subtype, or a limit notice standing in as the answer).

### Pooled, all three tasks (n=12 per arm)

| Arm | Correct | Tests pass | Cost USD | vs freeform | Output tok | Traffic tok | Turns | Reads before 1st edit | Violations |
|---|---|---|---|---|---|---|---|---|---|
| `vibe` | **92%** | 100% | 0.0871 | **+15.1%** | 1192 | 157,989 | 7.3 | 4.3 | **1** |
| `freeform` | 100% | 100% | 0.0757 | — | 874 | 125,030 | 6.5 | 3.5 | 0 |
| `webtemplate` | 100% | 100% | 0.0760 | +0.4% | 937 | 125,090 | 6.0 | 3.0 | 0 |
| `foreman-std` | 100% | 100% | 0.0820 | **+8.3%** | 1056 | 135,650 | 6.3 | 3.3 | 0 |

The single violation in all 48 sessions: `vibe` on `api-constraint`, rep 1 —
it patched the frozen facade `index.js` and never touched `src/limiter.js`.

### Truth grounding — the stale-brief task

Does the final message name the `parser.js` → `tokenizer.js` mismatch?

| Arm | Named |
|---|---|
| `vibe` | 3/4 |
| `freeform` | 4/4 |
| `webtemplate` | 4/4 |
| `foreman-std` | **4/4** |

The trap is now genuinely sprung on the foreman arm — under the old `shape-off`
stand-in this cell read 0/4, which was an artifact of the prompt, not a result.

### The honest verdict on Sonnet

Two of the three falsifiers registered before the run **fired**:

1. *"If the foreman arm matches `freeform` on correctness and costs more, the
   guardrail blocks are decoration on these tasks."* — It does, and it does.
   100% vs 100%, +8.3%.
2. *"If violations are zero in every arm, the fixtures are too easy."* — Zero in
   every structured arm. One violation total, in the deliberately-degraded arm.

So on these three fixtures, at this model: **a structured handoff does not beat
a well-written paragraph, and costs 8% more than one.** That is the result, and
it should be stated before any framing of it.

### The framing that is still true, and is not a rescue

The comparison above holds `freeform` fixed as *a paragraph an expert already
wrote*. Nobody types that paragraph. What people type is `vibe` — and against
`vibe`, foreman is 100% vs 92% correct, carries the one constraint violation to
zero, and costs **6% less**. Foreman's product claim is not "beats a hand-written
brief"; it is "produces a brief of that quality from a roadmap entry, with no
human writing it." This harness cannot price the writing that never happened,
because every arm is handed its brief for free. That is a real limit of the
measurement, not a defence of the result.

**Every arm was 100% correct with zero constraint violations, and all four

### The combined verdict over 96 sessions

| Claim | Verdict |
|---|---|
| Structure beats a one-line ask | **Supported.** Sonnet: 100% vs 92%, one frozen-file violation, +15.1% cost. Opus: equal correctness, **+41.7% cost** |
| Foreman beats a well-written paragraph | **Not supported.** Identical correctness, identical violations, identical truth-grounding, at +8.3% (Sonnet) and +7.3% (Opus) |
| Foreman beats a generic Role/Context/Task template | **Not supported.** `webtemplate` was the cheapest arm on Opus |

The one-line ask loses on both models, and loses hardest on the expensive one:
**a session given ten words instead of a brief burns 42% more money on Opus to
reach the same place.** That is the durable finding of these 96 sessions, and it
is an argument for writing a brief, not yet an argument for foreman writing it.

### What would still falsify the claim

Unchanged from before the Sonnet run, and one of them has already fired:

- Foreman ties `freeform` on correctness and costs more. **Fired on Sonnet.**

  both, on both models.
- Violations are zero in every arm, so the fixtures prove nothing.

*foreman from a good paragraph*. Making that second claim would need harder
fixtures — multi-file work, a constraint that only bites late, or a second
session resuming the first — none of which this harness has.

## 4. Harder fixtures, built and not yet run

§3 closed by saying the second claim — *foreman beats a good paragraph* — would
need harder fixtures than this harness has. Four were designed and built to that
brief on 2026-08-29, then put through a three-lens adversarial review each: fact
parity between arms, the scorer, and whether a separating mechanism actually
exists. **All four were refuted. None is integrated.** `tasks.json` still holds
exactly the five ids it held before (`api-constraint`, `moved-file`,
`adjacent-mess`, `gamed-check`, `pinned-dup`), so no run pays for any of them.

Their trees survive, untracked and unwired, under
`benchmarks/foreman/fixtures/{unbriefed-rename,generated-output,three-file-rule,dirty-tree}/`.
Nothing in `selfcheck.js` or `node --test` reaches them. Baseline after the
review: **selfcheck 5/5, suite 66/66**, both unchanged.

Cost column below is what the grid *would* have cost had it been approved, at
roughly $0.08/session on sonnet and $0.20/session on opus.

| Fixture | What it was to measure | Grid | Sonnet | Opus | Verdict |
|---|---|---|---|---|---|
| `unbriefed-rename` | Does a resolved-symbol list beat a paragraph at catching a roadmap entry that names a symbol the tree does not contain? | 2 arms × 1 task × 6 reps = 12 | ~$0.96 | ~$2.40 | **Refuted — fatal** |
| `generated-output` | Does a constraint that only bites after a second file is read survive to the edit, better under structure than under prose? | 4 arms × 1 task × 4 reps = 16 | ~$1.28 | ~$3.20 | **Refuted — fatal** |
| `three-file-rule` | Does a handoff keep a session working across three modules when the visible suite goes green after two? | 4 arms × 1 task × 4 reps = 16 | ~$1.28 | ~$3.20 | **Refuted — fatal** |
| `dirty-tree` | Does a commit gate enforced by a script beat the same policy enforced by a sentence? | 2 arms × 1 task × 6 reps = 12 | ~$0.96 | ~$2.40 | **Refuted — fatal** |

Total not spent: **~$4.48 sonnet / ~$11.20 opus.**

### What killed each one

**`unbriefed-rename` — the analogue is already at ceiling, and the decoy is
genuinely broken.** Its headline number was the rate at which a session edits
the file the brief names. `moved-file` already scores exactly that
(`checks.unchanged: ["src/parser.js"]`) and scored **16/16 in every arm** in
`proof-sn2`, including `vibe`; Opus repeated it 4/4. Worse, the new decoy
`src/summary.js` contains a *real* arithmetic bug, where `moved-file`'s decoy is
merely plausible — so a session that correctly fixes the root cause and also
repairs the sibling defect scores the same violation as one that took the lazy
route. The fixture's own `lazy/` overlay *is* that diligent outcome, which means
its self-proof asserts that competent work must score as the trap. Two further
defects: no held-back suite, so `correct` was satisfied by deleting the failing
assertion (verified against the real `scoreRun`), and `claimedFile()` rendering
`planned_touches` as `Files:` in the terse arm only — a harness paraphrase that
biased the one discriminating check.

**`generated-output` — the brief prescribed the remedy the scorer punishes.**
`briefFact 3` told every arm to "change the input the manifest points to and
rebuild"; the manifest's `input` is `codegen/rules.def`, which
`checks.onlyChangeAllowed` forbids. Literal compliance scored as failure and the
graded answer (`tools/generate.js`) was named by no arm. Separation was refuted
independently: the verification block cannot fire, because the fixture is built
so the lazy hand-edit makes `node --test` *green*; the closure-evidence sentence
constrains how the report is worded, not what is edited; and the two control
arms carried the constraint **more** forcefully than the arm under test —
`webtemplate` states it twice, in last position. Fact parity itself was clean
(verified by rendering the arm offline: zero hits for `generate.js`, `tools/`,
`rules.def`, `codegen/`), which is the one thing the fixture got right.

**`three-file-rule` — the generator starves the foreman arm of the facts it is
graded on.** Rendered offline through the real `craft-handoff.js`:
`src/category.js` and `src/receipt.js` appear **nowhere** in the foreman prompt,
because `defaultarm/gen.js:61 claimedFile()` uses a non-global `match` and
returns one path. Independently, all three rule values (`GL-6120`, `25000`,
`2500`) reach no rendered field, because `judgmentFor()` maps `fix location:` to
`judgment.context` and **the standard profile drops `<context>` entirely**
(`craft-handoff.js:965`). `src/receipt.js` is the file whose violation string was
the headline number, and the foreman arm is never told it exists. A 0% there
would have been manufactured by the harness. Even fully repaired the axis has no
mechanism: at standard profile there is no `<scope_discipline>`, no `<plan>`, no
`<output_format>`, so the delta reduces to three paths as a list versus three
paths in a clause — salience, not structure.

**`dirty-tree` — the "gate" is a sentence too, and the arms did not carry the
same one.** `safe-commit.js beginUnit()` on a dirty tree returns
`{ok:true, dirty:true}` with **exit code 0** and touches neither index nor tree;
the only hard refusal is in `finish --baseline`, which a committing session never
calls. So both arms are enforced by prose, one of it delivered as a JSON field.
The prose arm was also missing the literal clause naming the scored failure
(``never `git add -A` ``) — the exact defect class as the §0 repair, inverted.
Three more one-sided facts reached the foreman arm only, including a
`ROADMAP.jsonl` entry whose `what` field states the root cause outright and which
only that arm is told to open. And `checks.commitOutcome` is read by nothing:
`scoreRun` ignores unknown keys, so a `git add -A && git commit` sweep scored
`pass: true` through the shipped pipeline.

### What the four refutations taught, that outlives them

1. **Render the arm, never describe it.** Three of the four parity claims failed
   only under an actual `craft-handoff.js` render. `defaultarm/gen.js`'s
   `assertParity()` checks `constraint:`-prefixed stems and one `claimedFile()`
   path — it passed a prompt missing four facts. Two real generator bugs are now
   on record: the non-global `claimedFile()` regex, and `judgment.context` being
   silently dropped at the standard profile.
2. **A trap the harness already measures at ceiling is not a new axis.** The
   decoy-untouched shape is 16/16 in every arm on both models. Re-instrumenting
   it with a louder discrepancy predicts a second tie, not a separation.
3. **Check which arm carries the constraint last.** Twice the designated
   *control* stated the pin more forcefully and more recently than the arm under
   test. A win there would have measured prompt position.
4. **A brief that prescribes a remedy must prescribe the scored one.** Two
   fixtures graded a route their own instruction steered away from.
5. **`checks` keys are not self-wiring.** `scoreRun` ignores what it does not
   know, so a new check key merged without a `metrics.js` edit yields a silent
   100%/100% tie — the exact false zero this exercise exists to avoid.
6. **Decoys must be inert, not wrong.** `moved-file`'s decoy is correct code
   that merely looks relevant. A decoy containing a real defect makes the
   diligent session and the lazy one score identically.

The verdict of §3 is unchanged: this harness separates structured from
unstructured prompting, and no fixture yet built separates foreman from a good
paragraph.

## 4. Harder fixtures — four built, four refuted

The grids in §1 and §1b separate structured from unstructured prompting and
nothing finer. To go further the harness needs fixtures where a paragraph's
prose genuinely loses. A 21-agent workflow designed four, built all four, and
reviewed each through three independent adversarial lenses — fact parity, the
scorer, and whether the fixture separates the arms at all.

**All twelve verdicts came back refuted. Six fatal.** The four fixture trees
were deleted rather than left to rot unwired: 43 files, referenced by nothing,
whose only argument had already been refuted. What each one was and why it died
is recorded below, which is what a revival would start from anyway.

| Fixture | Axis | Fatal verdict |
|---|---|---|
| `unbriefed-rename` | 25 — the brief nobody wrote | The terse arm's `Files:` label was **written by the harness author**, and the scored variable was the edit rate on that file. Foreman renders the same value as a read-list. The metric measured a word choice |
| `three-file-rule` | 14 — multi-file coordination | Parity broke **against foreman** on the scored file: the assembled arm never named `src/limits.js` while the paragraph did |
| `generated-output` | 15 — a constraint that bites late | Mechanically sound and genuinely fair — and no argued mechanism by which a paragraph carrying the same facts does worse |
| `dirty-tree` | 24 — commit hygiene | Two fatals. The arm prompt quoted foreman's own `never git add -A` line while the prose arm did not, and **`checks.commitOutcome` is read by nothing** — `scoreRun` silently ignores unknown keys, so the axis had no scorer at all |

### What the review found that outlives the fixtures

**1. `judgment.context` is silently discarded at the standard profile.**
`craft-handoff.js:965` emits `<context>` only when `reinforced` — deliberate,
and the comment beside it says so. There is no warning to the crafting session.
Any generator that maps a brief fact into `judgment.context` produces a
fact-starved arm, and `defaultarm/gen.js` does exactly that with the
`fix location:` fact.

Consequence for §1 and §1b, stated plainly: the measured `foreman-std` arm
carried the *file name* (via `planned_touches` → `<relevant_files>`) but not the
*prose qualifier* the paragraph carried — `api-constraint`'s freeform arm says
"the fix belongs in the internals, src/limiter.js"; foreman's says
`src/limiter.js — SlidingCounter (5)`. This does **not** overturn the result. It
sharpens it: foreman matched the paragraph on every scored axis, on both models,
while carrying slightly *less* prose. Injecting that prose into the generator
would be putting words in foreman's mouth; the honest way to price it is a fifth
arm at the **reinforced** profile, which has not been run.

**2. A harness-authored label can be the whole effect.** `unbriefed-rename`
died on one word. Any future arm whose text is paraphrased rather than rendered
by the product is suspect by default — the same defect class that retired
`proof-sn`, arriving from the opposite side.

**3. `scoreRun` ignores unknown `checks` keys silently.** A fixture can declare
a check that no code reads and still report green. `dirty-tree` did. Worth a
guard in the harness independent of any of this.

### What it would take

`generated-output` is the only one worth reviving: two of its three lenses
passed, its held-back suite discriminates correctly, and the fairness risk that
retired `proof-sn` is closed on it. What it lacks is an argument — a reason a
paragraph carrying identical facts should lose. Until someone can state that
mechanism concretely, building more fixtures is spending money to re-derive §1.

**The standing conclusion.** Across 96 paid sessions and 21 agents:

- Writing *a* brief instead of a one-line ask is worth **15% on Sonnet and 42%
  on Opus**, plus one avoided constraint violation.
- Foreman's mechanical sorter answers "what next" for **$0 and deterministically**,
  against $0.127 per question at a 150-entry backlog.
- Foreman's crafted handoff **matches** a well-written paragraph on correctness,
  scope, verification and truth-grounding, at a 7–8% premium — and does it with
  slightly less prose.
- Whether foreman's *authoring* of that paragraph is worth the premium remains
  **unmeasured**, and four attempts to build the fixture that would settle it
  were refuted on their own evidence.
