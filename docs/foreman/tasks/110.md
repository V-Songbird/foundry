title: Measure scope drift against the pre-fold touches snapshot, not a new field
date: 2026-07-26
---

## Decision
The entry's own `touches`, snapshotted inside `cmdUpdateStatus` before the close folds
the derived files in, is the prediction. No new schema field is added. The close
subtracts in both directions — `untouched` for predicted paths nothing touched,
`unpredicted` for touched paths nothing predicted — and appends the result to `notes` as
one `scope drift — …` line, also returning it as `scope_drift`. Matching is prefix-aware
via `coversPath`, so an area hint covers every file beneath it. The record never gates:
the close still exits 0 and returns `ok:true` however wide the diff. An entry that
predicted nothing, and a close with no `commit`/`staged` behind it, both stay silent, and
an already-recorded line is never appended twice.

## Context
This entry's `what` assumed a stored "predicted file surface" that decision 106 had
declined to create — 106 kept the expected file surface as a prompt-side constraint
bullet, never a persisted field. But a prediction was already there: `touches` at
creation time is exactly the user's guess, and the close overwrites it in place. The
snapshot recovers it at the only moment it still exists.

## Alternatives rejected
- A new `predicted_touches` field — duplicates what `touches` already holds at creation
  time, and every existing entry would carry an empty one forever.
- Exact set subtraction — `touches` is an area-level hint, so a directory entry would
  report drift on every file beneath it.
- Gating or warning on a wide diff — the entry states the comparison is subtraction, not
  judgment; a wide diff describes framing, not failure.
- Recording drift when the entry predicted nothing — every touched file would read as a
  surprise, which is noise rather than signal.

## Consequences
`touches` now carries two meanings in sequence, prediction then footprint, and the
snapshot line in `cmdUpdateStatus` is the only thing separating them — moving the fold
above it would silently make every drift empty. Never turn the note into a gate or a
status change.

The submodule limitation this doc originally recorded as open is closed. `git show` at
the project root cannot see a commit that lives inside a submodule, so a close from one
derived nothing at all — `touches` never grew and drift never computed. `gitFilesIn` now
falls back to each path listed in `.gitmodules` and prefixes what it finds, so derived
paths read the same way `touches` does. The root repo is always tried first, so a commit
it can see is never looked for in a submodule.
