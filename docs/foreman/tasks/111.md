**Superseded 2026-08-01 (entry 146, foreman 1.0 close):** Call 5c / Q4 "match the recommendation" was deleted with the whole model-advice surface. Historical only.

## Decision
On the `Execute here` destination the model and effort recommendations are stated
together and followed by their own question — `Call 5c` in craft-prompt, `Q4` in the
roadmap skill — asked once per handoff, after the execution-mode question and before the
first task row exists. Two options: proceed as-is, or the user switches the session
first. It never sets a model, never blocks, never records anything, and neither
recommendation reaches the assembled prompt. The other two destinations are untouched,
since there the model is a dispatch value `Call 6` already asks for.

## Context
Entry 101 made effort advisory prose on every destination, and `Execute here` skips the
model question entirely because no dispatch value exists there. So the one recommended
destination was also the only one where a recommendation had nothing to act on it. The
user chose the interrupting version over a stated line, on the reasoning that a line is
exactly what gets skimmed past.

## Alternatives rejected
- Folding it into the execution-mode question as a fourth option — those options are
  tracking modes and are mutually exclusive; the user needs to answer both, and one
  option list cannot carry two independent answers.
- Detecting the mismatch and switching automatically — hook input carries no model at
  all, and effort is readable only inside a hook, never by a skill.
- Stating both halves and asking nothing — that is entry 101's design, and it is the
  behavior this entry exists to replace.
- Asking once per task row — a split run would repeat the same question for one handoff.

## Consequences
`Execute here` now costs one extra round trip on the most common path; that is the price
of the interruption being the point. The question must stay a question — turning it into
a gate, or into anything that writes a model or effort anywhere, breaks the constraint
that the operator's answer IS the comparison. Any future destination that gains a real
dispatch value should use `Call 6` instead of this call. Drift pins in
`check_prompt.test.js` hold the wording, the once-per-handoff rule, the before-the-first-row
timing, and the never-a-gate rule in both skills.
