title: Core + Quiet by default; capabilities, not dials; disable governs runtime only
date: 2026-07-28

## Decision
Hush's four surfaces get explicit boundaries. **Core** (tool-output compression, sidecars,
stats) and **Quiet** (mid-turn silence, final-message discipline) are the default
experience. **Voices** (presets, craft-style) and **Draft** (durable-document rewriting)
are opt-in surfaces a session invokes by name. Silent — suppressing the final message's
explanatory duty — is never a default; it stays an explicit choice.

Named sub-decisions:

1. **Disable semantics (1a).** `HUSH_DISABLE=1` governs everything hush does at
   *runtime*: every hook's output, context injection, state write, sidecar, and debug
   path. The forced output style is *activation state*, not runtime behavior — the
   harness reads `force-for-plugin` from frontmatter and no environment variable can
   reach it — so turning the style off stays a one-command action
   (`/hush:pick-style` stock hand-back, or uninstall). The README documents the two
   switches as two switches.
2. **Sidecar retention.** Delete at session end once a SessionEnd hook exists
   (entry 165). A documented compaction grace period only if entry 168's tests prove
   one necessary.
3. **Packaging.** One repo, one install. Modularity lives in activation and claims:
   Core always on, Quiet/Voices/Draft opt-in. No split packages.
4. **No dials.** Reaffirmed: hush exposes capabilities, never compression-intensity
   levels or profiles.
5. **Command wrapping.** Off by default, labeled invasive-compat where documented.
   The trailing-subshell wrong-exit-code case gets a test and a doc caveat (entry 166).
6. **Benchmark gate numbers.** Deferred to Wave F kickoff; proposed together with the
   batch plan and cost estimate for explicit approval.
7. **Positioning.** Specialist for noisy, log-heavy, multi-turn work — not a universal
   default — until workload-aware activation is proven.

## Context
Hush mixed cost reduction, quiet interaction, voice styling, and durable-document
rewriting under one promise, though they carry different risks and success measures.
The 2026-07-27 product contract posed seven open decisions; the 2026-07-28
ground-truth pass (strategy doc §2) resolved the facts they hinged on. Decisive for 1a:
six of seven hooks are already fully gated behind `HUSH_DISABLE`, including every disk
write — the real leaks are exactly two, the nudge hook and the frontmatter-forced
style, and the second is unreachable by any runtime mechanism.

## Alternatives rejected
- **Dynamic style un-forcing** — the harness reads frontmatter when it loads styles;
  there is no runtime channel, so an env-gated style is unimplementable, not merely
  undesirable.
- **Split packaging (hush-core / hush-voices)** — doubles release and doc surface for
  code that already activates modularly; honest claims achieve the separation.
- **Intensity dials or profiles** — standing no-dials rule; a dial invites tuning
  folklore where a capability invites a yes/no adoption decision.
- **Universal-default positioning** — the benchmark shows a specialist profile
  (regressions up to +28.3% on ordinary tasks; the win concentrates in noisy
  multi-turn work). Claiming universal savings is the claim the contract flagged.

## Consequences
Entry 162 implements the literal runtime disable and rewrites the README's disable row
as two switches. Entry 169 builds the Core/Quiet separation on this boundary. Entry
173 rewrites public claims to the specialist position. Entry 165 lands session-end
sidecar deletion; 166 the wrapping caveat; 175/176 wait on Wave F's gated numbers.
Anyone proposing a dial, a split package, or a universal-savings claim argues against
this record first.

## Findings
The disable audit refuted the review's broadest reading: state writes do not leak —
every disk write in all seven hooks sits behind a guard. The two real leaks
(silence-nudge's missing check; the forced style) are what made splitting "runtime
disable" from "activation state" honest rather than a compromise. Range-read handling
and wrapper-metadata loss were confirmed as real transform defects and stay build
entries (163), not decisions.
