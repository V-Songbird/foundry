---
id: 231
title: The fix ceiling belongs to the verification block, not to a profile
date: 2026-08-13
---

## Decision
The bounded fix ceiling ships on every handoff that carries a
`Verification (REQUIRED):` block, standard and reinforced alike, and the gate
requires it on both. `checkPrompt`'s guard drops its `reinforced &&` term and
keeps living inside the existing non-`--research` branch, so a pure-investigation
handoff with no retry loop is still never asked for a ceiling. The three places
that disagreed now say the same thing: `craft-handoff.js` already emitted the
line unconditionally and does not change, `check-prompt.js` binds what already
ships, and `prompt-template.md`'s profile section names the ceiling as part of
the verification block the standard profile keeps rather than as a reinforced
extra.

## Context
Three sources of truth disagreed. `prompt-template.md`'s "Handoff profiles"
section listed the ceiling among the reinforced-only blocks, `check-prompt.js`
gated it behind `reinforced`, and `craft-handoff.js` appended it whenever
`hasVerification` was true — which is to say on every real prompt of either
profile. So no assembled prompt was ever missing it, and the documented rule was
describing a behavior the assembler had never had. Anything touching that line
would silently pick a side. The tie is broken by what the sentence does: it
bounds the retry loop the `Run:`/`Expected:` pairs open, and the standard profile
carries those pairs, so a standard prompt without the ceiling is a prompt with an
unbounded loop. That is the failure the ceiling exists to stop, and it is not
made cheaper by the profile being short.

## Alternatives rejected
- Make the docs win and add a `reinforced &&` guard to `craft-handoff.js` — it
  would remove the ceiling from every standard prompt shipping today, trading a
  documentation inconsistency for a real regression in the profile that gets the
  least context.
- Leave the code as the truth and only fix the prose — the gate would still wave
  through a hand-written standard prompt with an unbounded loop, which is exactly
  the case the gate exists for.
- Give the ceiling its own constant and a separate standard-profile rule — a
  second thing to keep in sync for coverage the single check already has.

## Consequences
A hand-written standard prompt with a verification block and no ceiling now
fails the gate. Nothing assembled by `craft-handoff.js` is affected, on either
profile, because the emit site never had the guard. `standardPrompt()` in
`tests/check_prompt.test.js` builds its closing line from `FIX_CEILING_LINE`
like `goodPrompt()` already did, and a new test pins the requirement in both
profiles. The `[Foreman: 103]` comment that attributed the guard to that entry
is corrected: doc 103 decided where the ceiling lives and what it replaces, and
scoped it to the non-`--research` branch — it never scoped it to a profile, and
profiles did not exist when it was written.
