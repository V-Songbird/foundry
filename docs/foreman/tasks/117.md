title: Word the Execute-here question without implying a direction
date: 2026-07-26
---

**Superseded 2026-08-01 (entry 146, foreman 1.0 close):** the question this doc words was deleted. The no-direction principle may be reused, but nothing in foreman implements it today.

## Decision
The `Execute here` question reads "This task suggests <model> at <effort>. Run it there
instead?" — never "Raise the session to it?" or any other wording that names a direction
(raise, upgrade, bump, lower, downgrade). The block is called **Match the
recommendation** in `prompt-template.md`, `Call 5c — match the recommendation` in
craft-prompt, and `Q4 — match the recommendation` in the roadmap skill. Everything else
entries 111, 114, and 116 established is unchanged.

## Context
Entry 111 shipped the question as "Raise the session to it?". A live run on Opus at
medium effort drew "This task suggests Sonnet at medium effort. Raise the session to
it?" — Sonnet is a step *down* from Opus, so the sentence described the opposite of what
it was asking. This is not a rare edge: the recommendation is judged from the task, and
plenty of tasks suit a smaller model than the session happens to be running.

## Alternatives rejected
- Detecting the direction and picking the verb — the same wall entry 111 already hit:
  hook input carries no model at all, and effort is readable only inside a hook, never by
  a skill. Foreman cannot know which way the recommendation points, which is exactly why
  the wording must not claim one.
- Naming both directions ("raise or lower the session to it?") — longer, and still wrong
  in the third case where the session already matches.
- Leaving it and explaining the wording in the option descriptions — the question is the
  line the operator actually reads, and it was the line that was false.

## Consequences
The no-direction rule is now stated in all three files rather than left implicit, because
the failure recurs the moment someone rewords the question for brevity. Drift pins in
`check_prompt.test.js` assert the new question verbatim, the rule, its reason, and the
absence of the old string across the template and both skills. Any future wording that
compares the session to the recommendation — not just this question — is bound by the
same constraint for the same reason.
