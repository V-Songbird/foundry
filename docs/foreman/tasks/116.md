title: Gate the model and effort recommendations behind modelSuggestions, default off
date: 2026-07-26
---

**Superseded 2026-08-01 (entry 146, foreman 1.0 close):** modelSuggestions was removed with the model-advice surface; render-sections.js no longer reads it and init no longer asks. Historical only.

## Decision
`modelSuggestions` is a new `.foreman/config.json` boolean, default `false`, read by
`render-sections.js` alongside `fableEnabled` and surfaced in the same JSON the skills
already consume. When `false`, three things produce nothing: `prompt-template.md`'s
"Model fit" note, its "Effort fit" note, and the `Execute here` raise-the-session
question (`craft-prompt`'s Call 5c, `foreman:roadmap`'s Q4). The executing-model question
still runs on the dispatching destinations — a background `Agent` and a clipboard paste
both need a model named — but offers the plain list with no seeded default and no
`(Recommended)` label. A non-boolean value warns and falls back to `false`.

## Context
Entry 111 added the recommendation and entry 114 fixed how it is acted on, but neither
made it optional. A project that has already settled its model policy pays an extra
question on `Execute here` — the recommended, most common destination — plus a
model line and an effort line on every handoff, and had no way to decline. The user asked
for it as a setting, defaulted off.

## Alternatives rejected
- Gating the executing-model question too — that question is a dispatch value, not
  advice. Suppressing it would leave a background `Agent` call with no model to pass.
- Folding it into `targetModel` — e.g. treating `inherit` as "recommend" and a concrete
  pin as "don't". The two answer different questions: `targetModel` scopes how much
  detail a prompt spells out, `modelSuggestions` decides whether Foreman offers an
  opinion at all. A project can want a pin and no advice, or advice and no pin.
- Defaulting it on to match the behavior entries 111 and 114 shipped — the user asked
  for off, and off is also the answer that costs nothing to a project that never wanted
  the advice.
- Separate keys for the model half and the effort half — they are one recommendation
  stated in one breath, and entry 111 already established that. Splitting the switch
  would let a project enable half of a single sentence.

## Consequences
`init`'s Call 2b grew from a 2-question batch to 3, and the config write step now names
eight keys instead of seven. Anyone who saw the model and effort lines before this entry
will stop seeing them until they opt in — that is the intended change, and the README
settings table plus the changelog entry are where they find the switch. Drift pins in
`check_prompt.test.js` hold the gate wording, the default-off statement, the
`targetModel` independence rule, and the rule that the executing-model question survives
the gate, across the template and both skills. `render_sections.test.js` pins the
default, the pass-through, the non-boolean warning, and the independence from
`targetModel`.

Entry 115 attempted a different feature under the same request — capture of suggestions
the user voices in conversation — and was reverted in `b9de825`. Nothing from it
survives; if that idea is ever wanted it starts fresh.
