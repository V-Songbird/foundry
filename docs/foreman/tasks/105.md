---
id: 105
title: Ask for symbols in relevant_files, but never warn when one is missing
date: 2026-07-26
---

## Decision
The symbols-first rule is stated in the two places a human authors a citation —
the template's relevant_files authoring bracket, which now says why (a symbol
name is self-locating and survives edits above it, a line range is the first
thing to go stale between craft time and run time) and shows an unnamed-spot
example that still names its enclosing symbol; and `craft-prompt`'s Call 2 Q3,
which now asks for the functions or classes that matter instead of line ranges.
The checklist item stops offering "symbols or line ranges" as equal options.
`checkPrompt` gains NO symbol check: the existing path-like warning stays exactly
as it was, with a `[Foreman: 105]` comment recording that the omission is a
decision rather than an oversight.

## Context
Most of what this entry asked for was already in place before it was picked.
`scripts/resolve-symbols.js` extracts symbols at craft time, the template's step
0b already routes `files[].symbols` into the citation, the authoring bracket
already said to fall back to a line range only where no symbol covers the spot,
and `foreman:roadmap`'s pick branch already runs the resolver and cites what it
returns. What remained was the checklist item, `craft-prompt`'s question wording,
the fixture, and the one open judgment call the entry named.

That judgment call is the reason the gate stays silent. `foreman:roadmap` seeds
the citation from an entry's `touches`, which is area-level and frequently a bare
directory — `foreman/skills/` is a real recorded value — and that branch is
forbidden from exploring the codebase to upgrade it. A warning on a symbol-less
citation would therefore fire on a large share of roadmap handoffs for a
condition the crafting session is not permitted to fix, which trains the reader
to skim warnings rather than read them.

## Alternatives rejected
- Warn when relevant_files has a path but no symbol — fires on roadmap handoffs
  seeded from a bare-directory `touches`, which the pick branch may not upgrade.
- Make it an error — same objection, and it would break the pass-through
  outright rather than merely nagging.
- Detect symbols by regex and warn only when a path looks file-shaped but carries
  no name — a heuristic on prose, warning about the shape of a sentence rather
  than about anything verifiable.
- Manufacture more work to match the entry's `what` — the entry's own premise had
  aged; the honest close is what actually remained.

## Consequences
A prompt citing bare directories stays gate-clean forever; the symbols-first rule
lives entirely in authoring guidance, enforced by drift pins on the wording rather
than by inspection of any assembled prompt. Never add a symbol-less warning to
`checkPrompt` without first changing the roadmap pass-through, and the comment in
the code says so. `craft-prompt`'s Call 2 Q4 was corrected in the same commit
(approved by the user): it still asked for "read/explore, then analyze/check,
then implement" after entry 104 moved the read step into the plan block, and now
asks for two steps.

## Findings
The docs review that produced this entry flagged the whole idea as depreciating
scaffolding — worth revisiting whether symbol citation still earns its authoring
cost once models locate symbols reliably without help. That doubt is not resolved
here and should not be treated as settled. The counter-argument that kept it: the
cost is now paid by `resolve-symbols.js`, not by a human, so the scaffolding is
close to free even if its value decays. Should that change, the deletion is
cheap — the rule is prose in two files plus four drift-pin assertions, with no
runtime behavior depending on it.
