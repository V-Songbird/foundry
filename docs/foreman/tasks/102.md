id: 102
title: Record model and effort as closed-set fields written only at close time
date: 2026-07-25
---

## Decision — the choice, named, in one paragraph

`model` and `effort` are optional entry fields validated against closed sets
(`MODELS` = haiku|sonnet|opus|fable, `EFFORTS` = low|medium|high|xhigh|max)
and accepted **only** by `update-status`, never by `add`. Both are omitted
entirely when unset, matching the `doc`/`kind` contract. A shared
`validateRan` helper covers both, throwing a message that names the accepted
values. The roadmap skill's embedded close paragraph now asks the closing
session for both, and bakes in the model literally on the background-`Agent`
path only — there the confirmed executing-model answer is the `Agent` call's
own `model` value, so craft time genuinely knows it. Effort is never baked
in anywhere.

## Context — the constraint that forced it

Entry 101 shipped the recommendation half; a recommendation cannot be
calibrated without a record of what actually ran. Neither field is
observable: hook input carries no model, and the `Agent` tool takes no
effort argument, so effort is whatever the executing session was already set
to. Both are therefore self-reports, and the only honest place to collect a
self-report is the close.

## Alternatives rejected — one line each: the option and the single reason it lost

- Free strings instead of closed sets — a corpus is only comparable if its
  labels are, and a typo would be indistinguishable from a real value.
- Accepting both on `add` — an entry being created has not run yet, so
  there would be nothing to report.
- Passing them through `cmdNextCandidates`' projections — candidates are
  unrun by definition, so the fields are always absent there.
- Warning when the recorded value differs from the recommended one — that
  difference is the signal being captured, not an error.
- Baking the model into every destination's close call — only a background
  `Agent` dispatch knows what will actually run; `Execute here` never asked,
  and a pasted prompt lands wherever the user pastes it.

## Consequences — what future work is committed to, plus any never-touch warning

`MODELS` and `EFFORTS` need a one-line extension when a new model or effort
tier ships; the comment above them says so. Any later measurement over this
corpus must scrub or isolate first — the fix for a closed entry lives in
both git history and ROADMAP.jsonl, and both are agent-readable, so a replay
against the commit's parent would otherwise read its own answer.

Never auto-detect either field. The absence of a key means unrecorded, which
is deliberately different from a default value.
