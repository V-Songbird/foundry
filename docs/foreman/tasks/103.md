id: 103
title: Place each handoff guardrail where nothing can drop it
date: 2026-07-25
---

## Decision
The three guardrails land in three different places, chosen by what can remove
them rather than by what reads best. The precedence rule (facts are hypotheses,
the prescribed approach is a decision already taken) goes *inside*
`<truth_grounding>`, because that block is compared verbatim against the
template by `checkPrompt` — placing the sentence there enforces it for free,
with no new constant and no fixture that has to be kept in sync by hand. The
no-invention rule goes on its own line *after* `</background>`, not inside
`<relevant_files>` where it conceptually belongs, because `background` is a
legal member of `omitSections` and a rule inside it would silently vanish for
any project that omits it. The fix ceiling replaces the verification block's
closing sentence outright: `"If it fails, iterate until it passes."` becomes
`"fix and re-run — but after two failed fix attempts, stop and report…"`.
The latter two get the `AUTONOMY_SENTENCE` treatment — a module-level constant
in `check-prompt.js`, a `norm`-tolerant `includes` check in `checkPrompt`, and a
drift pin in `check_prompt.test.js` — and the fix-ceiling check lives inside the
existing non-`--research` branch, so a pure-investigation handoff with no
verification block is not asked for a ceiling it has no loop to bound.

## Context
`truth_grounding` already tells the destination to trust reality over the
prompt, but it says that about *facts*. The prompt also prescribes an approach,
and nothing said which authority wins when the codebase makes the prescription
unworkable rather than merely contradicting a stated fact. A capable session
notices that conflict and has to guess; a weaker one never notices — the same
prompt then produces run-to-run variance that gets misread as an effort-setting
effect. The two neighbours are the same shape: an unresolvable cited symbol
invites invention, and an unbounded retry loop invites widening the change until
the tests go green.

## Alternatives rejected
- All three inside `truth_grounding` — cheap to enforce, but it turns one
  guardrail block into a catch-all and buries the fix ceiling far from the
  verification block it bounds.
- No-invention inside `<relevant_files>` — reads best, but `omitSections`
  can drop the whole `background` block and take the rule with it.
- A separate `checkPrompt` check for the precedence rule — the verbatim
  `truth_grounding` comparison already fails on its absence; a second check
  would be a second thing to keep in sync for no added coverage.
- Keeping `"iterate until it passes"` and adding the ceiling beside it — two
  sentences that contradict each other in the same block is the exact ambiguity
  this entry exists to remove.
- Making the fix ceiling a warning rather than an error — the old line would
  keep shipping in every prompt assembled from an older habit, which is the
  failure mode, not an edge case.

## Consequences
Any prompt assembled before this change now fails the gate — including this
entry's own handoff prompt, which was gated and split into tasks minutes
earlier. That is intended: the gate reads `prompt-template.md` at run time, so
a stale prompt is supposed to be caught. Two test fixtures (`goodPrompt`'s
`task_rules` and `RULES_WITH_FIELDS`) now build their closing line from
`FIX_CEILING_SENTENCE` instead of hard-coding it, so a future reword of the
ceiling changes one constant, not three files. Never move the no-invention line
back inside `<background>` — the `omitSections` hole is the whole reason it sits
where it does, and the test `the no-invention line sits outside <background>`
pins that.
