title: Keep ${CLAUDE_PLUGIN_ROOT} unexpanded in assembled prompts and reject pinned cache paths
date: 2026-07-26
---

## Decision
The rule that `${CLAUDE_PLUGIN_ROOT}` travels into an assembled handoff prompt as
that literal string is stated in three places, not one: `prompt-template.md`
(a `[Foreman: 107]` paragraph immediately before the XML fence, plus a checklist
item and a line in the Mechanical gate section), `skills/roadmap/SKILL.md`'s
entry-paragraph bullet, and `skills/craft-prompt/SKILL.md`'s "Assemble the
prompt" section. `checkPrompt` enforces it with `PLUGIN_CACHE_PATH_RE`, a
module-level exported regex matching a `plugins/cache/<owner>/<plugin>/<version>`
path on either slash, raised as an error. The version segment is the trigger —
an unversioned plugin path is left alone.

## Context
The entry's `what` asked for the statement in `prompt-template.md` alone, but the
template is not where the leak happens. A skill's markdown reaches a crafting
session with `${CLAUDE_PLUGIN_ROOT}` already substituted by the harness, so the
session following `skills/roadmap/SKILL.md` literally reads a version-pinned
cache path in the very instruction it is copying from. `prompt-template.md` is
opened with `Read`, so its own text stays literal — which is exactly why a rule
placed only there would describe a problem the reader cannot see in front of
them. Each skill therefore says the rule where the expanded path appears, and
names the asymmetry as the reason.

## Alternatives rejected
- Move the bookkeeping commands behind a slash command so no path appears in
  prompt text at all (the entry's own "consider") — the unexpanded-variable rule
  plus a gate error already close the replay failure, and a slash command adds a
  second invocation surface that every destination would have to be taught.
- State the rule only in `prompt-template.md`, as the entry's `what` asked — the
  template's copy is unexpanded, so it is the one file where the reader has no
  expanded path in view to correct.
- Make the finding a warning rather than an error — a warning is skimmed, and the
  failure it guards is silent until a replay is attempted months later.
- Detect any absolute plugin path rather than a versioned one — `${CLAUDE_PLUGIN_ROOT}`
  can legitimately resolve to a version-less development checkout, and flagging
  that would fire on prompts that replay fine.

## Consequences
Every crafting path must now type the variable back rather than paste what its
own skill text shows; the gate catches the slip, and its error message says the
fix is to restore the variable, never to strip the command. The regex is the
single detection point — a future plugin-cache layout change (a different segment
order, a non-semver version) needs `PLUGIN_CACHE_PATH_RE` updated, not a second
check. Never relax it to ignore the `cache` segment: a project path that merely
contains a version-shaped directory would then start erroring.

## Findings
The archived prompt named in the entry's notes pinned `0.27.0-alpha`; the plugin
cache in this environment is currently at `0.46.0-alpha`, so that prompt is
already unreplayable — the failure the entry predicted has happened.
